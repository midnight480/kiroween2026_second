# 公開 API (API キーで使う)

スクリプト、CI、チャットボットから、サインインした人の帳面に灯を登録・取得するための API です。利用者向けの説明は `api.html` (ヘルプとは別のページ) にあり、このファイルは設計と運用の決まりをまとめます。実装は `worker/v1.ts` です。

## 決定事項

- **キーは Clerk の API キーを使う。** 発行、名前付け、取り消し、最後に使った日時の表示は Clerk のアカウント画面 (アバター → アカウントを管理 → API キー) に任せる。自前の発行画面と鍵のテーブルは作らない (ユーザーの判断: 発行画面はクラウドのアカウントの中に統合してよい)。
- アカウント画面には「API の使い方」のページと、ユーザーボタンのメニュー項目を足し、`api.html` へつなぐ (`src/auth.ts` の `accountExtras()`)。
- 使い方の説明は `api.html` に置く。ヘルプ (`help.html`) には短い案内と、`api.html` へのリンクだけを置く (ヘルプを重くしない)。
- API が触れるのは、キーの持ち主 (Clerk のユーザー) の帳面だけ。ゲストの帳面 (`localStorage`) は API から見えない。
- 削除 (燃やす) は API に入れない。誤操作やスクリプトの暴走で消えないようにするため。

## 前提の設定 (Clerk ダッシュボード)

- Clerk ダッシュボードで、API キーの機能 (ユーザーの API キー) を有効にする。有効にするまで、アカウント画面に「API キー」のページは出ず、`apiKeys.verify()` も通らない。
- 開発用インスタンスと本番インスタンスの両方で有効にする。

## エンドポイント

ベースは `/api/v1`。全て `Authorization: Bearer <key>` が必要。

| メソッドとパス | 動き |
|---|---|
| `GET /projects` | プロジェクトと名簿 (`id`, `name`, `created`, `members[{id, name, role}]`)。作った順 |
| `GET /tasks` | タスクの一覧。期限の近い順。`?project=` と `?status=todo\|doing\|done` で絞る |
| `POST /tasks` | 登録。`201` と `Location` |
| `PATCH /tasks/{id}` | 件名、期限、メモ、担当者、状態の変更 |

入力の検証は画面と同じにする。

| 項目 | 決まり |
|---|---|
| `title` | 前後の空白を除き、連続する空白は1つにして 1〜80文字 |
| `due` / `minutes` | どちらか一方。`due` はタイムゾーン付きの ISO 8601。1分以上先、1年以内。分単位に切り捨てる |
| `project` | POST だけ。省くと最初に作ったプロジェクト。プロジェクトが1つもなければ `409` |
| `note` | 500文字まで。`null` か空文字で消す |
| `assignee` | タスクのプロジェクトの名簿にいるメンバーの id。`null` で担当者なし |
| `status` | POST は `todo` / `doing`。PATCH は `done` も。期限後の完了は `late: true` |

- PATCH で期限を後ろへ動かすと `extended` を1増やし、気配による見た目の縮み (`penalty`) を0に戻す (看板の「蝋を足す」と同じ)。
- 呪いの演出 (`cursed`) は API では変えない。1タスク1回の決まりは看板が守る。
- 統計 (消した灯の数) は端末の `localStorage` にあるため、API での完了は数えない。

## 保存の形

API が書く行は、看板が書く行と同じ JSON (`src/store.ts` の `Task`) にする。`tasks` テーブルの `data` にそのまま入るので、看板は変換なしで読める。

- 看板は開いている間、1分ごとと、タブに戻ったときにサーバーを読み直す (`src/main.ts` の `pullLedger()`)。中身が変わっていなければ再描画しない (`sync.ts` の `differs()`)。ドラッグ中、長押し中、ダイアログやメニューを開いている間、送信待ちの変更がある間は読み直さない。
- 看板と API が同じタスクをほぼ同時に変えた場合は、後に書いたほうが残る (行ごとの上書き)。

## 上限

| 項目 | 値 | 超えたとき |
|---|---|---|
| 回数 | 1つのキーで1分に60回 | `429` と `Retry-After` |
| 本文 | 16 KB | `413` |
| 1タスクの大きさ | 32 KB (`/api/sync` と同じ) | `413` |
| 未完了 | 1プロジェクト60件 (看板と同じ) | `409` |
| 保存数 | 1人2,000件 (`/api/sync` と同じ) | `409` |

- 回数は `api_rate` テーブル (`db/migrations/0002_api_rate.sql`) で数える。キーそのものは保存せず、SHA-256 のハッシュを主キーにする。数えるのは Clerk への問い合わせの前 (でたらめなキーの連打でも Clerk を呼びすぎない)。
- 検証済みのキーは Worker のメモリに60秒だけ覚え、Clerk への問い合わせを減らす。そのため、取り消したキーが止まるまで最大1分かかる (`api.html` にも書いた)。

## セキュリティ

- 他のサイトの Web ページからは呼べない (CORS のヘッダーを返さない)。キーをブラウザのコードに入れさせないため。
- エラーの応答に、DB や Clerk の詳細を載せない。詳細は Worker のログにだけ出す。
- Organization の API キー (`subject` が `org_`) は受け付けない。組織の帳面はまだないため。

# 音の設計 (Web Audio API)

音はすべてブラウザの Web Audio API で、その場で合成します。音声ファイルは使いません (`AGENTS.md`)。このファイルは、音の役割、ノードの組み合わせ方、モバイルでの注意点をまとめます。実装は `src/audio.ts` です。

## 音の役割

音も演出と同じく、機能を助けるために鳴らします。基本は静寂で、音は「何かが起きた」ことを知らせる情報です (`design-principles.md` の間)。

| 音 | 関数 | 鳴る場面 | 伝える情報 | Safe mode | 状態 |
|---|---|---|---|---|---|
| 部屋の空気 | `startRoomTone()` | 入場後ずっと | 「静かな部屋にいる」。無音との差で、他の音が際立つ | 同じ | ✅ |
| 紙の擦れ | `rustle()` | ドラッグ中 | ドラッグしていること | 同じ | ✅ |
| 囁き | `whisper()` | 気配 | 何かがいる。画面を見ていなくても気づける | 同じ (人影の代わりに鳴る) | ✅ |
| 蝋燭が消える | `candleOut()` | 完了、期限切れ | 1件が終わったこと | 同じ | ✅ |
| 心音 | `heartbeat()` | 呪いの段階3 | 何かが近づいている | 鳴らさない (段階3以降を飛ばすため) | ✅ |
| 血 | `bloodSound()` | 呪いの段階2 | 画面が切り替わること | 同じ | ✅ |
| ドローン | `startDrone()` | 呪いの段階3〜4 | 緊張が高まっていること | 鳴らさない (同上) | ✅ |
| 衝撃 | `lunge()` | 呪いの段階5 | 期限切れ (1タスク1回) | 鳴らさない (大音量のため。同上) | ✅ |
| 遠い歌声「くる」 | (候補) `kuruSong()` | 残り60秒で1回 | 期限が「来る」。数え歌 (10秒) の前の予告 | 同じ (大音量ではないため) | ⬜ |
| 炎のゆらぎ | (候補) | 残り20%未満の蝋燭がある間 | 消えかけた蝋燭があること | 同じ | ⬜ |
| 数え歌の拍 | (候補) | 残り10秒 | 秒読みのテンポ | 同じ | ⬜ |
| 定位した気配 | (候補) | 人影が出た側から鳴る | どちらの端に何かがいるか | 囁きだけ定位させる | ⬜ |

新しい音を足すときは、この表に「伝える情報」と Safe mode の振る舞いを書いてから実装します。

## 仕組み: ノードをつないで音を作る

Web Audio は、ノード (音の部品) を線でつないだグラフです。音源から出た信号が、加工のノードを通って、最後にスピーカー (`ctx.destination`) へ届きます。

```
音源                     加工                         出口
───────────────────     ─────────────────────────    ─────────────────────
AudioBufferSource ──┐
 (ホワイトノイズ)    ├─▶ BiquadFilter ─▶ Gain ──▶ master Gain ─▶ destination
OscillatorNode ─────┘    (音色を削る)    (音量の     (0.7 / Mute で 0)
 (正弦波・のこぎり波)                    時間変化)
```

いまの `audio.ts` は、この1本の形を組み合わせて全ての音を作っています。

| 部品 | ノード | 役割 | 例 |
|---|---|---|---|
| ノイズ | `AudioBufferSourceNode` | 乱数で埋めた2秒のバッファをループ再生。息、紙、炎など「ザー」系の素 | 起動時に1つだけ作り、全ての音で使い回す |
| 発振 | `OscillatorNode` | 一定の高さの音。低音、ドローン、衝撃 | `thud()` は90Hz→30Hzへ下げて「ドン」 |
| フィルタ | `BiquadFilterNode` | 帯域を削って音色を決める | lowpass 160Hz = 部屋の空気、bandpass 2.5〜5.5kHz = 紙、highpass 3.5kHz = 吹き消す息 |
| エンベロープ | `GainNode` + `AudioParam` の予約 | 立ち上がりと減衰。音の「形」 | `setValueAtTime` → `exponentialRampToValueAtTime` |
| マスター | `GainNode` | 全体の音量と Mute | `setTargetAtTime` で0.05秒かけて切り替え (プツッと鳴らない) |

### 組み合わせのレシピ

同じ部品の組み合わせ方を変えるだけで、音の種類を増やせます。音声ファイルなしで足りる、というのがこの方式の利点です。

| 組み合わせ | 作り方 | 向いている音 |
|---|---|---|
| 重ね | 違う帯域の bandpass ノイズを2本同時に鳴らす | 囁き (`whisper()` は1.8kHz付近と3.1kHz付近を重ねて、子音っぽくしている) |
| 掃引 | フィルタの `frequency` や発振の高さを時間で動かす | ドローンが開いていく (lowpass 120Hz→900Hz)、衝撃の落下 (1400Hz→180Hz) |
| うなり | 近い周波数の発振を重ねる (55Hz と 58.3Hz) | 不安定な低音。和音にならない気持ち悪さ |
| LFO | 低い周波数の `OscillatorNode` を `GainNode` 経由で別ノードの `AudioParam` につなぐ (`lfo.connect(lfoGain).connect(filter.frequency)`) | 炎のゆらぎ、囁きの震え、心音のような揺れ |
| 定位 | `StereoPannerNode` を挟み、`pan` を -1 (左) 〜 1 (右) にする | 人影が出た側から気配を鳴らす。音で方向が分かる |
| 残響 | `ConvolverNode` に、減衰するノイズで作ったインパルス応答を渡す (ファイル不要) | 和室や廊下の響き。囁きを遠くに置く |
| 歪み | `WaveShaperNode` にカーブを渡す | 衝撃の割れ。ラジオやビデオテープ風の音 |
| こだま | `DelayNode` + 帰還用の `GainNode` | 数え歌の「ひとつ…」の余韻 |
| リミッタ | `DynamicsCompressorNode` を master の後ろに置く | 音が重なっても割れない、耳を傷めない |

ConvolverNode のインパルス応答は、ノイズを指数関数で減衰させたバッファで作れます。

```ts
function makeRoomIR(ctx: AudioContext, seconds = 1.6, decay = 3): AudioBuffer {
  const len = Math.floor(ctx.sampleRate * seconds);
  const ir = ctx.createBuffer(2, len, ctx.sampleRate);
  for (let ch = 0; ch < 2; ch++) {
    const d = ir.getChannelData(ch);
    for (let i = 0; i < len; i++) d[i] = (Math.random() * 2 - 1) * Math.pow(1 - i / len, decay);
  }
  return ir;
}
```

### バスの構成 (推奨)

いまは全ての音が直接 `master` に入っています。音が増えたら、用途ごとのバス (まとめ用の GainNode) を挟むと、Safe mode や Mute を用途単位で制御できます。

```
環境音バス (部屋の空気、炎のゆらぎ) ──┐
効果音バス (紙、蝋燭、囁き) ──────────┼─▶ master Gain ─▶ DynamicsCompressor ─▶ destination
呪いバス (血、心音、ドローン、衝撃) ──┘
```

- Safe mode のとき、呪いバスの上限を下げる。いまも Safe mode では呪いの段階3以降を飛ばすので、心音、ドローン、`lunge()` は鳴らない。新しい呪いの音も同じ扱いにする。
- リミッタは threshold -10dB、ratio 12 程度から調整する。大音量の上限を決めておく。

### 書き方の決まり

- **時間は `ctx.currentTime` で予約する。** `setTimeout` はタブが裏に回ると遅れる。いまの `heartbeat()` は `setTimeout` を使っているので、`start(t + i * interval)` の予約に置き換える候補。
- **0 に向けて exponential ramp しない。** `exponentialRampToValueAtTime(0)` はエラーになる。`0.0001` まで下げてから止める (いまのコードの書き方)。
- **使い捨ての音源は `stop()` を予約する。** 止めた音源はブラウザが片付ける。ずっと鳴る音 (部屋の空気、ドローン) だけ参照を持つ。
- **同時発音数を抑える。** ドラッグ中の `rustle()` は連打されるので、最短の間隔を決めておく (モバイルで重くなるため)。
- **ノイズバッファは1つを使い回す。** 再生位置 (`start(t, offset)`) をずらせば、毎回違う音に聞こえる。
- **音だけで情報を伝えない。** Mute でも同じことが画面で分かるようにする (`features.md` の合格ライン)。

## 遠い歌声「くる」(候補)

貞子の映画のような「遠くから女の歌声が聞こえてくる」怖さを、期限の予告に使います。

### 著作物との線引き

- 『リング』の主題歌「来る -きっと来る-」の**旋律と歌詞は使わない**。「くーるー、きっとくるー」をなぞった節回しも避ける。
- 借りるのはジャンルの型だけにする: 遠くで女が一人で歌う、古いビデオテープのように音程が揺れる、ノイズに埋もれる、途中で途切れる。
- 旋律は自作する。日本の旋律らしさは**都節音階** (ミ・ファ・ラ・シ・ド。半音を含む陰の五音音階) で出す。
- 言葉は「くる」の一語だけ、または言葉なしのハミング (「んー」「うー」) にする。「くる」は普通の日本語で、期限が来ることと重なる。

### 鳴らす場面と、機能との関係

| 段階 | 残り時間 | 音 | 伝える情報 |
|---|---|---|---|
| 予告 | 60秒 | 遠い歌声「くる」(1回、6〜8秒) | 期限が来る。まだ間に合う |
| 秒読み | 10秒 | 数え歌「ひとつ、ふたつ…」 | 最後の10秒 |
| 期限切れ | 0秒 | 呪い | 遅かった |

- 1タスクにつき1回だけ鳴らす。同時に複数の蝋燭が60秒を切っても、重ねて鳴らさない。
- 歌っている間、その蝋燭のそばに薄く「くる」の字を出す。Mute でも同じことが分かるようにする (音だけで情報を伝えない)。
- 英語版でも「くる」の字は日本語のまま出す (AGENTS.md の i18n の決まり)。

### 合成の組み立て

音声ファイルなしで、声に近い音を作ります。人の声は「声帯の振動 (音源)」を「口の形 (フォルマント = 強く響く帯域)」で削ったものなので、同じ構造をノードで組みます。

```
声帯: のこぎり波 OscillatorNode (高さ = 旋律)
  ├─ ビブラート: 5.5Hz の LFO → frequency (±20 cent)
  └─ テープの揺れ: 0.4Hz の LFO → detune (±15 cent、ゆっくり不安定)
        │
        ├─▶ bandpass F1 ─┐  母音「う」: F1 ≈ 350Hz、F2 ≈ 1200Hz (女性の声)
        ├─▶ bandpass F2 ─┼─▶ 子音・息: 短い highpass ノイズを重ねる (「く」の破裂)
        └─▶ bandpass F3 ─┘
                │
        lowpass 2.5kHz (遠くにいる) ─▶ Convolver (和室か廊下の残響) ─▶ 呪いバス
                                                                   ▲
                       テープノイズ: highpass ノイズを小さく常に重ねる ┘
```

- 「く」: 2〜4kHz の短いノイズ (30ms) のあとに母音「う」。「る」: フォルマントを一瞬下げて戻す (舌が弾く感じ)。聞き取りにくければ、ハミングだけにする。
- 遠さ: lowpass を低め、残響を多め、音量は部屋の空気より少し大きい程度。近づいてくる感じは、lowpass を少しずつ開けて出す。
- 途切れ: 再生中に1〜2回、0.1〜0.3秒だけ音量を0にする (ビデオテープのドロップアウト)。
- `speechSynthesis` (ブラウザの読み上げ) は使わない。端末ごとに声が違い、日本語の声がない端末もあり、機械的に聞こえて作品の空気が壊れるため。

### 確認すること

- 聴いた人が『リング』の主題歌を思い出すほど似ていないか (似ていたら旋律を変える)。
- スマートフォンのスピーカーで、歌声だと分かるか。
- 60秒のデモ (`burns 1 min`) で、追加してすぐ鳴りすぎないか。燃焼時間が60秒以下のタスクは、残り50%で鳴らすなどの調整が要る。

## ブラウザの制限 (自動再生)

ブラウザは、ユーザーの操作なしに音を出すことを禁じています。

- `AudioContext` は、ゲートの「Light the candle」のクリック処理の中で作る (いまの `initAudio()`)。処理の中で `await` を挟む前に作ること。iOS Safari は、クリックやタッチの処理と同じ流れで作らないと、`suspended` のまま鳴らない。
- 作った後も `ctx.state` が `suspended` になることがある。次のユーザー操作 (`pointerdown`) で `ctx.resume()` を呼び直す。
- 再読み込みでゲートを通らずに盤面に入る設計にしたら、最初の操作で `initAudio()` を呼ぶ。

## モバイルと PWA での注意

PWA としてホーム画面から開く前提です (`mobile.md`)。

| 状況 | 起きること | 対応 |
|---|---|---|
| アプリを裏に回す、画面を消す | iOS では `ctx.state` が `interrupted` か `suspended` になる | `visibilitychange` で表示に戻ったら `resume()` を試し、失敗したら次の `pointerdown` で再開する |
| 電話の着信、他のアプリの音 | 同上 | 同上 |
| iPhone の消音スイッチ | Web Audio は消音スイッチに従って鳴らない (既定) | 既定のまま従う。ホラーを電車で大音量で鳴らさないため。`navigator.audioSession.type = "playback"` で無視できるが、使わない |
| 裏に回っている間 | タイマーが止まり、期限切れの判定もされない | 戻ったときに `checkExpiry()` が一度に複数件を処理する。呪いを連続で再生しないよう、まとめ方を決める (`mobile.md` の要判断) |
| 電池 | 部屋の空気は常に鳴っている | 裏に回ったら `ctx.suspend()` して止める |
| 端末のスピーカー | 低音 (30〜90Hz) がほぼ出ない | `thud()` や心音に、200〜400Hz の倍音か短いノイズを重ね、小さいスピーカーでも「ドン」と分かるようにする |
| 振動 (候補) | Android は `navigator.vibrate()` で振動できる。iOS は非対応 | 心音と衝撃に合わせる候補。Safe mode では使わない。振動だけで情報を伝えない |

## 確認の手順

1. `npm run dev` を開き、ゲートを通る。部屋の空気がかすかに聞こえる。
2. `?debug` 付きで `__t.fire(2)` (囁き) と `__t.curse()` を再生し、通常と Safe mode の両方で聴く。
3. Mute をオンにして、全ての音が止まり、機能が全部使えることを確かめる。
4. スマートフォンで、裏に回して戻したあとも音が鳴るか確かめる (iOS Safari、Android Chrome)。
5. 端末のスピーカーとヘッドホンの両方で、衝撃の音量が痛くないか確かめる。
